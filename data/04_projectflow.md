# ProjectFlow product specification

> Fictional demonstration content. Not a real vendor claim.

ProjectFlow coordinates work packages, project milestones, contractor responsibilities, issues and change requests on industrial capital projects. A work package may have an owner, due date, dependencies, status and links to engineering records.

Core functions: configurable project dashboards; issue tracking; milestone dependencies; change-request registers; action ownership; document links; and controlled status reports. Supported import for baseline schedules is CSV; direct native scheduling-system integrations are not included by default.

The change process records an initiating issue, affected packages, assigned reviewers, decision, target date and closure evidence. If DesignHub is deployed, a change can reference an engineering document revision. ProjectFlow does not automatically determine the commercial cost of a change or certify its technical validity.

ProjectFlow can be used by EPC contractors and owners, with separate project-level permissions. It is not a replacement for a full enterprise resource planning platform, a contract management system or a scheduling engine. It provides coordination and traceability, not automated construction execution.

A pilot should validate the organization's work-package taxonomy, status conventions, reporting cadence and contractor-access model.
